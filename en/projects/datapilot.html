The problem

Small businesses keep their sales in messy spreadsheets, PDFs and handwritten ledgers. Before any analysis, the data must be trustworthy, without losing track of what was changed.

The goal: a workflow that ingests these files, checks every column, proposes fixes the user approves and publishes analysis-ready tables.

02

The approach

  1. 1 · Parquet

    Freeze the source

    The raw file is kept as is in a Bronze layer, with audit columns (ingestion time, file, row number).

  2. 2 · Python

    Infer a data contract

    Types, required fields, uniqueness, ranges (rating ≤ 5, quantity ≥ 0) and consistent labels, inferred from column meaning.

  3. 3 · Pandas

    Fix with approval

    Duplicates, typos (“Casblanca”), inconsistent amounts: every fix is proposed, approved and reversible.

  4. 4 · Parquet

    Publish Silver and Gold

    Silver: typed, cleaned data. Gold: business tables (revenue by product, monthly trend, column profile).

  5. 5 · DuckDB

    Trace and query

    A log of every run (SHA-256 fingerprint, durations, row counts), a read-only SQL console and a JSON API.

  6. 6 · RapidOCR

    Read handwritten ledgers

    Skew correction for photos, OCR confidence per row and human review before any calculation.

03

The application

Bilingual English and French interface. Each screen answers one question: how good is the data, what was fixed, where does each number come from.

05

Takeaways

Traceability

Never overwrite

The Bronze layer and the run log make every published number explainable.

Limitation

Validate in the field

The contract is inferred and OCR was measured on simulated handwriting: to be confirmed with real shop owners.

Scope: local prototype on synthetic data, without multi-user authentication or production hosting.
